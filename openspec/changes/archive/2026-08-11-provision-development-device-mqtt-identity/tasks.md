- [x] 1.1 以測試先行實作 Device inventory 不保存 credential、Non-secret device inventory 與 Identity consistency：`device-inventory.json` 唯一對應 physical label、`PC-000001`、`pc-mini`、`device-PC-000001` 與 `petcare-c7483/devices/PC-000001`，duplicate、principal/firmware mismatch 與 secret-like key/value 必須在 mutation 前失敗；以 `npx vitest run devices/development/device-inventory.spec.ts` 與 repository secret scan 驗證。
- [x] 1.2 以測試先行實作 Credential 以一次性人工 handoff 注入、Unique device credential 與 EMQX built-in database 與 strict TLS：`--apply/--rotate --secret-output-tty` 使用 EMQX HTTPS `/api/v5` access-control API、產生 non-superuser 32-byte base64url password，僅寫入預先開啟的 `/dev/tty` 一次，unsafe/write-failed path 零 mutation 或刪除新 principal rollback，stdout/stderr 僅有 sanitized JSON；以 `npx vitest run devices/development/provision-device.spec.ts` 驗證 secrets 不進 arguments、environment、files、logs 或 summaries。
- [x] 1.3 [P] 以測試先行實作 Registry read-before-write、Canonical publisher identity 與 Enabled registry alignment：preflight 要求 `clientId == deviceId`、`username == device-{deviceId}`、Topic productModel/deviceId、payload deviceId、inventory 與 firmware 一致（主線 contract 不在 payload 重複 productModel），並以 Application Default Credentials read-only 核對 `petcare-c7483/devices/{deviceId}` document ID、deviceId、productModel 與 `ingestionStatus: enabled`；以 `npx vitest run devices/development/registry-alignment.spec.ts` 驗證 mismatch/disabled 狀態 typed failure且 EMQX write adapter 未呼叫。

## 2. ACL 與 lifecycle

- [x] 2.1 以測試先行實作 ACL 僅允許發布自身 canonical telemetry topics、Username-scoped deny-by-default ACL 與 Own-topic publish ACL：username-scoped built-in database rules 只允許自身 QoS 1、retained=false 的 `events/urination` 與 `status/battery`，末尾 `#` deny all；Node `node:tls` MQTT 5 probe 必須以 PUBACK/SUBACK 或 Broker close 判定兩個 positive 與 `events/battery`、跨裝置、legacy、commands publish、commands subscribe negative cases，timeout/ambiguous ack 失敗；以 `npx vitest run devices/development/verify-device-acl.spec.ts` 驗證 rule order、strict `mqtts://:8883` TLS 與完整 probe matrix。
- [x] 2.2 以測試先行實作可回復 lifecycle 與 Credential lifecycle verification：runbook 與 command sequence 驗證 initial connect、同 username rotate 後 old password 拒絕/new password 接受、revoke 後拒絕，partial mutation 必須 rollback，所有 stdout summary 只含 mode、deviceId、principal、status、verification names；以 `npx vitest run devices/development/credential-lifecycle.spec.ts` 及 operator 明確執行的 sanitized live rehearsal 驗證。
- [x] 2.3 以測試先行實作 Firmware identity 與 retry metadata 遵循主線契約、Non-retained bounded QoS publishing 與 Stable firmware retry identity：firmware template 固定 strict-TLS `mqtts://:8883`、QoS 1、retained=false，拒絕 QoS 0/2、retained true 與 TLS bypass；`retry-after-disconnect.json` 的 retry 必須逐欄保留 canonical Topic 以及 payload 的 eventId、eventType、deviceId、schemaVersion、sequence、recordedAtMs、firmwareVersion 與 measurement fields，且依主線 contract 不在 payload 重複 productModel；以 `npx vitest run devices/development/firmware-config.spec.ts` 的 policy table/fixture assertions 及 `npm run check` 驗證 Web dependency graph 與 Browser bundle 未新增 MQTT package。
